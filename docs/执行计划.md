# 执行计划与 Android 验收

> 2026-10-02。已完成现状与设计整理；新功能仍待实现。需求见产品规划 F01–F14，风险见现状评估 R01–R14，本地保证见 L01–L12。历史“已完成”状态不沿用。

## 1. 顺序和依赖

先重现现有构建，建立持久化故障与迁移基线，再用领域规则和事务存储逐步替换现有 Flutter 内核。数据安全与新 UI 同一版本验收，不先发布无法安全升级的重构。服务器不是 A 的前置条件。

```mermaid
flowchart LR
  A0[构建与技术验证] --> A1[领域规则 SQLite]
  A1 --> M[旧数据迁移]
  A1 --> UX[三类记录 回顾]
  M --> Bk[文件备份恢复]
  UX --> N[提醒与异常]
  Bk --> A3[Android 验收]
  N --> A3
  A3 --> B[WebDAV]
  A3 --> C0[同步协议验证]
  B --> C[小型自建与官方同步]
  C0 --> C
```

## 3. 第一批可执行任务

1. ENG-01：重现现有版本并建立固定工具链 CI，记录 19 个已有测试实际结果；不能只修改期待掩盖问题。
2. DATA-01：实现 R01/R02/R09/R14 的故障回归、事务仓储与启动恢复，UI 提交后确认。
3. DOMAIN-01：计划历史、暂停／归档区间和统计表驱动算例。
4. MIG-01：版本分派、未知字段、ID 映射、自动保护副本与中断重试；真实样本和合成样本分清。
5. UX-01：空白开始、三类记录、今日双分区、数据中心低保真验证。
6. ANDROID-01：冷启动动作日期、重启重排、SAF 持久授权和读回。
7. RELEASE-01：真实安装签名调查、正常覆盖路径、必要桥接方案和正式凭据策略。

## 7. 发布门禁

- P0 数据损失／错误覆盖为零；正常使用和升级丢数据不能以用户没备份为理由放行。核心 P1 未解决阻塞发布。
- 静态分析、领域/widget/真实 SQLite/迁移测试与 Android 集成通过；真机通知、密钥和覆盖升级不能用 mock 替代。
- 中端机性能目标：十万条数据下冷启动 P95≤2 秒、普通保存反馈 P95≤300ms、详情 P95≤500ms；至少 30 次 release/profile 样本，报告设备和分布，非当前实测结果。
- 正常权限非受限条件至少 20 次分散提醒，目标 19/20 在计划后 10 分钟内出现；是质量目标而非系统准点保证。受限／强停分别验证解释、恢复和不重复。
- 至少 14 天 Android 试用，包含覆盖升级、无云使用和一次完整恢复。无数据事故，维护者执行恢复演练。
- 正式签名、清单、16 KB 原生依赖兼容、源码 tag、校验和、隐私、恢复和第三方许可一致。iOS 不作为当前完成门槛。
- B/C 只有对应测试通过才可宣传。加密必须有参数／密钥生命周期／已知答案及篡改测试和评审记录。
