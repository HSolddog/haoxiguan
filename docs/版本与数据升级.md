# 版本、数据与安装迁移

> 2026-10-02。旧说明原样保存在[历史目录](history/2026-07/版本与数据升级.md)。本轮不修改应用包名、版本、签名或用户数据。正常覆盖升级不要求用户先配置备份，可靠性见[本地数据完整性](本地数据完整性.md)。

## 1. 版本独立管理

| 类型 | 当前／目标 | 原则 |
| --- | --- | --- |
| App | 当前 1.0.3+4 | 可见版本与递增 build number，在 release commit 确定 |
| 旧状态 | 顶层 version=5，键 haoxiguan.app_state.v1 | 键名 v1 不等于格式版本 |
| SQLite schema | 新引入，从 1 起 | 每次变更有可验证迁移 |
| 备份 | 新 formatVersion=1 | 不依赖 App 版本猜格式 |
| 同步 | C 从协议 1 起 | capabilities，旧协议不兼容只暂停网络 |

未知未来格式先拒绝写入并提示兼容版本，不称其损坏，更不清空重建。

## 2. 自动本地迁移

1. A0 核实真实发行过的格式、安装用户和签名；当前代码只有部分历史夹具，不能声称已掌握 v1–v5 全部差异。
2. 检查新库和完成标记，已完成不再读旧状态播种。
3. 只读检测旧主键、备份键、旧库和迁移记录；主键缺失先找有效副本，双坏进入恢复界面。
4. 自动保存原始受控保护副本及摘要，校验结构并生成数量／异常预览；无需用户开启外部备份。原文不入日志。
5. 临时库迁移，校验 ID 映射、记录和备注逐字段、外键、计划区间、关键统计。成功才原子切换并写完成标记。
6. 中断以源摘要与 importId 幂等重试；失败保留旧数据，应用可进入只读／导出／重试界面。
7. 原始保护副本至少保留 30 天且直到新数据通过校验并有有效保护副本，不在迁移刚成功就抹掉源数据。用户外部备份始终可选。
8. 数据提交后重建提醒，副作用失败单独提示，不把已正确迁移的数据回滚或清空。

旧应用不识别新库，安装旧 APK 不是安全回滚。新版本已产生记录后必须保留增量、修复前进；不能回到旧快照而不说明丢掉的变化。任何日常升级不得建议卸载或清数据。

## 3. 语义映射

| 旧内容 | 新结构和处理 |
| --- | --- |
| 微秒 ID／seed ID | 固定 importId 的旧→UUID 映射，保留映射防重复 |
| 标题、图标、颜色、分类 | Habit/Category；名称不当主键 |
| completions | boolean 记录，日期原样，录入时间保留；无可靠偏移标未知 |
| notes | 独立 DailyNote，无打卡也保留 |
| 明确 scheduleType | 保留 daily/week/month 当前语义 |
| 缺 scheduleType、有 weekdays | 七天为每天，子集为固定星期，不强改为灵活周 |
| 已被旧程序迁为 week | 保留灵活周；丢失原语义不得猜测恢复 |
| exemptions、pausedAt | 原日期保留为休息／未闭合暂停，不猜测原因 |
| archived=true | 迁移日起归档，历史归档日期未知标记 |
| 奖励和心愿 | 原配置＋迁移时旧算法余额只读快照 |
| 外观和折叠 | 尽量保留；非法值可见回退 |
| 未知字段 | 保留 legacy 扩展或受控原文，报告未解释部分 |

旧数据没有计划修改史，以最后可知规则建立 legacyInferred 历史基线，保留原事实及旧统计快照，回顾说明升级前目标历史可能不完整；升级起才有完整版本。

非法日期、创建前异常记录、重复 ID、未知变体不静默裁掉；停止该迁移并给源数据导出和纠错报告。不能仅凭 seed ID 删除示例，旧用户可能已积累真实记录。

## 4. Android 签名和安装

当前包名 com.haoxiguan.haoxiguan，release 可回退调试签名，旧 Windows 脚本找特定历史调试证书。正式 release 必须固定正式身份，缺凭据失败，不回退 debug；私钥与密码受保护保存并做恢复演练。

| 情况 | 路径 |
| --- | --- |
| 尚无需要兼容的安装用户 | 正式渠道第一版固定正式签名 |
| 已有兼容正式签名用户 | 保持包名和证书，正常覆盖升级，自动数据迁移 |
| 已有历史调试签名，拟换正式证书 | 独立桥接计划，不能把签名不兼容称正常升级 |
| 旧签名不可得 | 先验证旧 App 可导出，不能假定能提取其私有目录 |

签名不兼容时普通覆盖可能失败。优先核实是否有可支持的签名升级／渠道机制，不假定覆盖所有旧 Android。若确需重新安装，先由旧签名桥接版或现有 JSON 导出形成独立可验证文件，再验解密、数量和内容，最后明确说明卸载会删除本机数据。该一次性身份迁移与用户要求的常规无损更新严格分开，不作为以后升级的标准做法。

任何桥接执行前确认实际用户与证书，不能为了新发布清掉旧用户记录，也不偷偷改包名绕过兼容问题。

## 5. 系统备份和路径

推荐显式排除数据库、旧原文、凭据和密钥参与 Android 自动云备份／设备迁移，保留非敏感外观偏好可选。核验 allowBackup、旧 full-backup 规则、Android 12+ data-extraction-rules 和合并清单及厂商行为。

显式备份用于换机，不依赖系统偶然带回密钥。路径和密钥别名不能随普通升级变化；若将来接入系统备份，要独立设计加密及恢复，不仅改开关。

## 6. 夹具与发布阻塞

覆盖空库、被编辑的 seed、仅备注、每天／固定星期／周／月、月底闰年、长暂停、归档、删除、负奖励、未知字段、主坏备份好、双坏、缺主键有备份、重复 ID、未来格式和十万记录。

对有效夹具逐字段比较事实和备注，验证二次启动不重复迁移、异常保留证据、新备份可全新安装恢复。对无效夹具确保活动库不变。尤其在未登录、未配置备份条件下覆盖安装并中断迁移；不能仅验证导出重装路线。
