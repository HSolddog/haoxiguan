# 数据、备份与同步规范

> 2026-10-02。A 本地与文件，B 自选备份，C 端到端加密同步。逻辑模型与协议设计，尚未实现；JSON Schema、OpenAPI、加密测试向量在相应技术阶段冻结。

## 1. 职责

保存是每次本地事务落盘；备份是不可变的历史快照；同步是合并设备变更（含删除）。三者独立。本地数据库持续可用，服务端离线不阻止记录。不能实时共享 SQLite/WAL 文件，也不能把整份 JSON 最后上传覆盖称为同步。

[本地数据完整性](本地数据完整性.md)不依赖 B/C。用户备份和服务端副本是额外恢复手段，不是弥补日常保存漏洞的前提。

## 2. 数据模型

共享实体用随机 UUID，UTC 记录真实时刻，YYYY-MM-DD 保存所属日期。设备时钟不充当唯一 ID 或冲突裁判。所有可同步实体有本地 revision、已知 serverRevision、createdAt、updatedAt，以及适用的 deletedAt。

| 实体 | 关键字段和约束 |
| --- | --- |
| Vault | id、schemaVersion、activeEpoch；一次一个活动空间，一个同步权威服务 |
| Habit | id、title、type、unit、scale、categoryId、sortKey；boolean/count/duration |
| ScheduleVersion | id、habitId、effectiveFrom/To、kind、weekdays、periodTarget、dailyTarget；区间不重叠 |
| AvailabilityInterval | pause/archive/rest、startDate/endDate，左闭右开；单日休息用一天区间 |
| CompletionRecord | id、habitId、localDate、value、recordedAtUtc、timezoneId、utcOffsetMinutes、source、revision |
| DailyNote | habitId、localDate、text、revision；每天独立于记录值 |
| Category | id、name、sortKey，名称不当主键 |
| ReminderRule | habitId、localTime、enabled、timezonePolicy；规则可导出，设备授权不导出 |
| ChangeLog/Outbox | opId、entityId、baseServerRevision、localRevision、deviceId、payload、state；与事实同事务 |
| DeviceState | deviceId、serverBinding、cursor；设备私有 |
| BackupJob | targetId、attemptAt、successAt、snapshotId、digest、result；密码放安全存储 |
| LegacyPayload | importId、sourceVersion、源摘要、未解释字段和迁移映射 |

完成型逻辑唯一键为习惯＋日期；数值每个独立动作有独立 entryId，重试沿用原 ID。备注按习惯＋日期唯一。服务器对象 ID 不暴露明文日期；对逻辑唯一对象使用稳定标识派生规则，跨设备可一致寻址。

定点数值避免浮点累计误差，时长整数秒。输入校验后事务写入事实和日志，提交后 UI 确认，再进行可重试提醒。启用外键、ID、数值、日期和计划约束。历史统计可重建，不作为唯一事实。

日期运算按日历加一，避免 DST 固定 24 小时错误。历史时区缺失标 unknownLegacy，不伪造原时区。新设备时区只影响之后记录。

## 3. A：可恢复备份与可读导出

### 3.1 格式

扩展名 .hgb，format=haoxiguan-backup、formatVersion=1；独立于 App 和数据库 schema 版本。UTF-8 JSON envelope 示例省略实际数据，不是可直接恢复的文件：

```json
{
  "format": "haoxiguan-backup",
  "formatVersion": 1,
  "appVersion": "<实际版本>",
  "encrypted": true,
  "crypto": {
    "suite": "argon2id-xchacha20poly1305-v1",
    "salt": "<base64>",
    "kdfParams": {"memoryKiB": 65536, "iterations": 3, "parallelism": 1},
    "nonce": "<base64>"
  },
  "payload": "<base64 密文>",
  "payloadSha256": "<密文字节摘要>"
}
```

明文内部含 manifest（snapshotId、createdAtUtc、sourceVaultId、sourceEpoch、dataSchemaVersion、数量）及逻辑数据和 legacy 扩展。首版无附件、无任意路径解包。算法／版本／salt／参数／nonce 的规范编码进入 AEAD 关联数据，必须发布确切字节编码和测试向量。

参数是低端机验证起点，尚非已测配置；绑定支持、耗时及内存通过后冻结。导入在派生前限制大小和 KDF 上界，防耗尽资源；文件初始上限目标 50 MiB，须用规模样本验证，不足则调整格式／上限并写明。密码错或篡改不得进入恢复事务。

每份文件独立 salt、随机 nonce，绝不重复 nonce；标准库实现 Argon2id 和 XChaCha20-Poly1305，不自研密码算法。SHA-256 只做传输损坏检测，不替代 AEAD 认证。文件密码不自动取账户密码或 WebDAV 凭据。

本地可明确选明文 JSON，保留 format/version 并可恢复。CSV 是可读分析格式，不是完整恢复：按习惯／计划／记录拆表，包含 ID、日期、单位、时区；转义并防公式注入。旧 JSON 走 legacy decoder。

### 3.2 保存与恢复

一致性读事务生成逻辑快照，临时写入→读回校验→标完成。不要只复制主 SQLite 文件漏掉 WAL。用户取消系统文件选择不能改变数据库。

恢复顺序：限额／版本／结构校验→解密→临时库外键、数量、计划和统计样本检查→预览→自动保护原数据→独占写入事务替换／安全切换→结果校验→重新检查提醒。

保护原数据失败则不替换；错密码、非法日期、重复 ID、未知未来版本、空间不足、中断均保持原库或完整回退。A 不自动合并不同备份。

不导出访问令牌、设备私钥、WebDAV 密码、OS 授权和同步游标。普通文件含独立可恢复的业务数据，不需携带旧同步主密钥。恢复为新的空间／设备身份，默认断开服务；重新连接须明确选择，避免把旧快照回推原空间造成复活或删除。

## 4. B：自选备份

A 通过系统位置保存文件，可交给任意网盘；B 首批内置 WebDAV，S3 按真实需求后续增加。WebDAV 只存不可变快照，不做实体同步。

HTTPS、最小权限应用密码和独立目录。自签名证书只能显式加入主机信任，不提供全局关闭 TLS 校验。存储凭据只留设备安全存储，不发给官方服务。

- 每台设备独立命名空间和随机 snapshotId，不争写 latest.json。
- 上传新对象→读回校验→写绑定摘要的完成标记；不依赖所有服务器都有原子 MOVE。
- 未完成对象不进入恢复列表；恢复前重验摘要和 AEAD。
- 401、404、429、证书改变、空间不足分别提示；指数退避且次数有界。
- 默认有变化时每天尝试一次，Wi-Fi 优先、前台补做；系统不保证准点。展示最近实际成功。
- 远端自动备份强制加密；保存密码／恢复材料并做一次验证，不能宣称运营者可代解密。
- 默认保留最近 7 个每日、4 个每周、6 个每月有效副本，重叠只算一份；成功新备份后才清理旧副本。
- 只清当前设备／配置下确认为本应用创建的对象，不删其他设备或用户文件，绝不先删最后一份有效副本腾空间。

两设备可读取彼此备份显式恢复，但不会自动合并文件；恢复按空间分叉和保护规则执行。

## 5. C：同步协议

### 5.1 接口和事务

| 意图 | 核心数据／保证 |
| --- | --- |
| capabilities | 协议／加密版本、大小和兼容性；不兼容只停网络，本地继续 |
| auth/devices | 用户授权、短期令牌、轮换刷新令牌、设备撤销 |
| push | vaultId、epoch、opId、opaqueEntityId、baseRevision、ciphertext；幂等 |
| pull | 空间、epoch、不透明 cursor、limit；按服务端提交顺序 |
| bootstrap | 一致快照及对应 high-water cursor，之后增量无缺口 |
| revoke | 撤销后不能上传或刷新；已下载内容不能远程收回 |
| delete/export | 账户删除状态和密文导出，独立于本机数据 |

CAS 检查 baseRevision；实体更新、opId 去重记录、serverRevision 和提交日志在同一 SQLite 写事务中提交。单实例序列化写入使游标按提交次序递增；以后换数据库也必须保留提交顺序语义，不能简单用预分配 sequence 假设不漏拉。

客户端 localRevision 与服务端 revision 区分；离线多次修改保留已知远端基线和未提交意图，不假造服务端版本。push 返回逐条结果，失败留 outbox；同 opId 不同内容拒绝。pull 应用和 cursor 前移同本地事务，未落盘不推进。回应丢失可安全重试。

### 5.2 冲突

409 后客户端取远端密文，解密对比共同 base、局部修改和远端版本。不能自动合并时把两份候选持久化，显示待处理；原地抛错不能丢本地候选。

| 场景 | 规则 |
| --- | --- |
| 两端同一天完成 | 相同逻辑键，合并为一次完成 |
| 完成与基于旧版本撤销 | 展示双方，用户确认，不按设备时间覆盖 |
| 两条独立数值录入 | 不同 entryId 相加；同 opId 重传只算一次 |
| 同条记录两端改总量 | 冲突，不将两个总量相加 |
| 同备注编辑 | 安全三方合并或展示双方，不能静默丢文本 |
| 不同字段修改 | 共同 base 且字段独立可合并，否则确认 |
| 计划同时修改 | 验证区间，不兼容候选不生效 |
| 删除与编辑 | 默认保留删除状态，编辑放冲突恢复区，可显式恢复 |
| 排序 | 确定性 sortKey，可再次排序，不影响事实 |

Tombstone 至少保留 180 天；更久离线设备标 stale，不直接上传旧增量。先保存本地差异、全量重新获取、处理差异。日志压缩／epoch 改变须通知客户端，不能让老设备复活已删对象。

### 5.3 加密与密钥

客户端生成随机 256-bit 内容密钥及独立用途的稳定 ID 密钥，用标准 KDF 做用途隔离；服务器只见密文和必要元数据。稳定寻址规则不随内容密钥轮换改变，稳定 ID 密钥不得用于加密内容。

AEAD 关联数据绑定空间、epoch、对象 ID、协议版本及基线元数据；精确编码和跨平台测试向量必需。每次加密用正确随机 nonce。服务器无内容解密钥匙，自建和官方均遵守。

新设备通过已有可信设备批准的受保护配对或离线恢复材料获得密钥。账户密码找回只恢复登录，不能代为找回内容密钥。仍有本地数据时可独立导出并新建空间；所有密钥、可信设备与可恢复副本都丢失时无法解密。

服务端仍知道账号、IP、设备、访问时间、对象大小／数量；不承诺匿名。它也可扣留数据；E2EE 不代替独立备份。客户端保存最高已见 epoch／cursor 检测回退，新设备需可信配对／恢复信息；AEAD 本身不保证识别全部回滚。

撤销失窃设备先断授权，再轮换未来内容密钥并分发给剩余设备；该设备已经读过的历史无法收回。轮换、配对重放、恢复码丢失和并发撤销必须做安全测试。

本地库的应用级加密是独立能力，当前规格以系统沙箱／设备保护为基线，增强见本地数据完整性，不把 E2EE 等同于手机上所有文件都已加密。

## 6. 服务恢复、迁出与删除

服务端从旧备份恢复后，在开放请求前进入恢复模式并更换 epoch；不得原样恢复旧 cursor 后直接接受旧设备增量。客户端保留未上传意图，先核验新基线，冲突明确处理。

| 动作 | 规则 |
| --- | --- |
| 断开 | 停网络，保留本地和未上传变更；清本机另确认 |
| 旧快照恢复 | 保护原库，新空间身份，默认不连接原服务器 |
| 官方迁自建 | 先导出验证，新空间新授权，目标核对后停旧服务；不迁 token |
| 删除账号 | 在线访问立即禁用，服务端按公布期限清除；是否清本地另选 |
| 到期／停服 | 本地可用，完整导出；远端只读宽限和清除期限提前公布 |

同一空间一次只绑定一个权威同步服务；备份目标独立。首版无联邦、多主服务器或透明跨服务迁移。自建运维仍需一致性数据库备份和异机恢复演练。

## 7. 协议验收

发布 JSON Schema、版本迁移夹具、加密测试向量、同数据统计期望；覆盖损坏、错密码、超大 KDF、重复 ID、数据往返。同步覆盖离线双端、重复请求、并发修改删除、分页中断、长期离线、服务端回滚、轮换、账户隔离和设备撤销。通过后才对外宣称可用。
