# 密钥轮换与服务运维

> 2026-10-02。当前支持维护期间切换到全新密钥空间；不承诺无停顿的原地重加密。Go/Flutter 真实 HTTPS 测试覆盖整条流程。应用仍标为实验性同步，原生联网验收、规模与独立评审继续进行。

## 1. 小型自部署

服务与客户端均为 MIT；只有本地磁盘 SQLite 和一个 Go 进程，不需要 Redis、SMTP、外部数据库或第三方身份系统。Go 1.27.1 构建静态 Linux amd64/arm64 二进制：

```sh
cd server
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o dist/haoxiguan-server-linux-amd64 ./cmd/haoxiguan-server
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o dist/haoxiguan-server-linux-arm64 ./cmd/haoxiguan-server
```

可选原生 systemd 模板为 `server/deploy/haoxiguan.service`：创建专用 haoxiguan 用户，将二进制安装到 `/usr/local/bin/haoxiguan-server`，状态目录 `/var/lib/haoxiguan`。默认只监听 `127.0.0.1:8787`。使用自己的域名及 HTTPS 反向代理；示例 `server/deploy/Caddyfile.example`。也可通过 `serve --tls-cert <PEM> --tls-key <PEM>` 直接提供 HTTPS，TLS 最低 1.2；该模式的证书续期由运维负责重启加载。

容器使用 scratch 与非 root UID/GID 65532，不包含 shell。先构建对应二进制，再：

```sh
docker build --build-arg TARGETARCH=amd64 -t haoxiguan-sync:local .
```

`server/deploy/compose.yaml` 将端口仅发布到主机回环，根文件系统只读、无额外 capabilities、1 vCPU/1 GiB 上限。部署前将专用绝对数据目录设为 UID/GID 65532、权限 0700，并设置 `HAOXIGUAN_DATA_DIR`；ARM64 同时设置 `HAOXIGUAN_ARCH=arm64`。只允许一个服务进程访问一份数据库，不使用共享网络盘。模板中的限制是资源上限，不等于已证明的用户容量。

账户与邀请只在服务器本机管理：

```sh
haoxiguan-server create-user --db /data/haoxiguan.sqlite --name owner --out /data/first-invite.json
haoxiguan-server invite --db /data/haoxiguan.sqlite --user <userId> --out /data/next-invite.json
```

容器运行时用 `docker exec <容器> /haoxiguan-server ...`，无需 shell。输出文件必须不存在、权限 0600；不要放公开站点、聊天日志或源码仓库。管理员通过已有可信渠道交给本人。邀请码 24 小时有效、一次性消费；每设备独立令牌。邀请只授权服务器访问，不提供内容密钥。

## 2. 维护式内容密钥轮换

适用：撤销丢失/不可信设备后的未来内容保护，或主动更新内容密钥。旧设备已经知道的过去内容无法收回。轮换创建新的随机 vault、地址密钥和内容密钥；新空间不接受旧授权，不沿用旧内容密钥或用旧密钥包装新密钥。

1. 保留一台可信设备及其完整本地数据。先在设备列表撤销不可信设备。不要卸载任何唯一持有数据或密钥的应用。
2. 管理员执行 `freeze-user --db <库> --user <userId>`。冻结在 SQLite 事务边界生效，之后的 push 返回 `maintenance_read_only`，pull 继续可用；各设备仍可离线记录。
3. 可信设备打开“重新授权与基线恢复 → 轮换前只读核对”。该流程完整接收远端内容，核对期间检查冻结状态及高水位未改变；合并本机未发送意图，遇到冲突先明确选择，再重复核对。旧固定 outbox 和候选先保存保护副本，不向被冻结空间写入。
4. 返回数据页导出并验证一份**完整 `.hgb` 加密数据备份**。`.hgr` 只有密钥，不能代替完整数据备份。确保准备设备仍可正常打开全部习惯。
5. 停止服务，执行：

   ```sh
   haoxiguan-server rotate-vault --db <库> --user <userId> --prepared --out <新邀请文件>
   ```

   `--prepared` 表示管理员已经完成上述可信设备核对和备份；服务器没有内容密钥，不能代替用户检查明文。命令只接受已经冻结的账户，并使用进程锁排除正在服务的实例。新 vault、旧密文归档、全部旧设备/会话/邀请废止、新邀请在同一事务提交。
6. 重启服务。可信设备保留本机数据，断开旧配置，使用新邀请按“首台设备”创建新空间内容密钥。导出新的 `.hgr` 并读回后再手动上传，核对完成。
7. 其他可信设备分别获得新邀请和新的 `.hgr`，以“加入已有数据空间”重新连接。有旧本地内容或旧同步历史的设备必须明确核对不同习惯，避免旧数据自动复活已删除记录。全新空设备可直接接收。

切换前中止：管理员 `unfreeze-user --db <库> --user <userId>` 恢复原空间，设备可继续同步，未发送事实仍在本机。切换后中断：旧授权保持失效，可信设备和已验证完整备份继续持有数据；重新发新空间邀请并完成上传，不自动回滚到旧密钥。新邀请输出写入失败时可用同一 userId 再发邀请。

旧密文保存在 `retired_vaults` 对应空间，不通过当前账户 API 提供，继续计入账户配额；不会因为轮换自动删除。显式删除远端账户会同时清除在线当前空间、历史和轮换归档。运维离线备份另有保存期，需向用户公开。

## 3. 服务备份与旧备份恢复

停止服务，运行 `backup --db <当前库> --out <不存在的备份文件>`。SQLite `VACUUM INTO` 包含已提交 WAL，随后 fsync；禁止只拷贝正在写入的主文件。定期将一致快照复制到独立存储，权限按凭据文件处理；服务库虽不含内容密钥，仍含账号和令牌摘要。

恢复时保留现有目录，把验证过的备份放到新目录。在 HTTP 尚未开放时执行 `rotate-epoch --db <恢复库>`；该动作同时废止所有旧会话、旧邀请和设备授权，防止已撤销授权随着备份回退恢复。之后启动、给可信设备新邀请；客户端使用匹配的恢复密钥，重新授权并“重新核对基线”。所有差异逐个核对，不能把旧服务器缺少的新记录当作删除。

若备份早于一次内容密钥轮换，旧密文需要当时的恢复材料；当前新密钥不能解密过去的旧空间。优先从可信设备或已验证完整加密备份重建新空间；不要为尝试恢复而删除唯一可读数据。

RPO 由维护者的实际一致快照频率决定；此处没有设定自动备份周期。当前演练验证了流程，未计时形成可承诺 RTO。数据库 schema 1 → 2 只增加维护标记和归档映射，事务升级；未来版本拒绝打开，不重置。

## 4. 可复现测试与边界

- `python3 tools/run_sync_integration.py` 自动创建隔离 Go 服务、测试 TLS 证书、两份邀请、Flutter 临时 SQLite；完成同步、冲突、撤销、冻结准备、完整备份、停服轮换、旧密钥拒绝、新恢复文件换机和删除远端后保留本地。私钥与邀请仅在临时目录，测试后删除，不关闭 TLS 校验。
- `python3 tools/container_smoke.py --image <已构建镜像> --output <报告>` 使用独立容器/卷，验证 UID 65532、只读根、1 CPU/1 GiB、持久重启、一致快照恢复、旧授权废止和不透明对象保持；退出清理仅本次创建的测试资源。
- 2026-10-02 Linux amd64 实测通过，见 `docs/验收记录/container-smoke.json`。空闲进程约 3.117 MiB / 1 GiB，**不是负载或容量结果**。ARM64 静态编译通过，尚未 ARM 实机运行。
- 数据接口精确字段见 `server/openapi.yaml`；加密/AAD、冲突及本地事务见[同步实现与验收](同步实现与验收.md)。HTTP 层仍有请求体、对象、配额和速率上限；服务器域名、证书续期、存储容量、离线备份与公开服务条款由部署者维护。
