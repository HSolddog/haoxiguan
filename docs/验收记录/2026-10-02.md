## 正常应用 API 24

源提交 `7273f5f08687dfd50f37edc43c2e86682fcfd3bf`，GitHub Actions Debug APK，API 24 x86_64 AOSP 模拟器。云环境无 KVM，本次使用软件模拟，不记录性能指标。为诊断软件渲染问题，仅本次启动 intent 设置 `enable-impeller=false`，未修改发布清单。

实际执行：

1. 首次打开没有示例习惯或伪造历史。
2. 界面创建 `OfflineRead20`、每天、布尔记录、无提醒，无备份或同步配置。
3. 点击完成，界面显示 1/1 和已完成。
4. `am force-stop` 后，通过 debug run-as 读取已停止应用的 SQLite 主文件和 WAL，在副本上校验：一个对应习惯、一条 value=1 且未删除的记录。
5. 重开应用，界面仍显示 1/1 和同一个已完成习惯。

[创建后的界面](android-api24-created.png)。测试均为本次创建的合成数据。

这是 Android 原生文件上的真实保存/进程重开检查，不是正常签名的版本覆盖升级，也没有模拟设备断电。API 35 软件模拟器此前出现系统 DeadSystemException/ANR，安装成功但不计为运行验收通过。

### 环境问题与证据范围

API 35/36 各遇到一次 AOSP Quickstep 桌面 ANR，夹具仅关闭可识别的系统桌面对话框一次，并保留 [API 35 事件](final-api-35/environment-events.json)、[API 36 事件](final-api-36/environment-events.json)和 CI 原始截图；应用断言照常执行。重复或非桌面 ANR 仍失败，因此这不是应用在真机长期稳定的证明。

运行 36999580510 的 API 24 首次在只读 ADB 文件查询退出 255 时中止，重跑停在 APK 安装超时；该运行整体不能计为全绿。最终成功运行使用驱动源码 `0f0eb6a6641b172f1ead49d5362f0489d531ec5c`：只对 stat/dumpsys/cat/getprop 的瞬时 255 最多重试三次，持久错误仍失败；输入、安装和写入不重试。旧系统先等待用户区解锁与包管理服务就绪，安装改用非流式方式。可选 JobScheduler 诊断输出不决定应用断言结果。

复用前 CI 以 `git diff --exit-code` 核对相对于 9d037f3 的 `lib`、`android`、`assets`、依赖锁、Dart 夹具、夹具构建器、冻结旧仓储和 Android 主工作流均未变；成功步骤和结果记录在运行 37001861441。临时复用工作流在取得证据后删除，以免长期依赖 14 天后过期的产物。正常 CI 继续从源码构建整套夹具，保留上述驱动兼容修复。
