# 产品规划

> 设计 2.1，2026-10-02。已确认：MIT、完成／计数／手动时长、加密、自建可能性、无同步备份也保持正常使用和升级数据完整。当前只制作验收 Android；本文的新能力待实现。

## 1. 定位和边界

好习惯是完全开源、离线优先、数据可带走的个人习惯记录与回顾工具，帮助用户持续行动，也允许暂停、调整和重新开始。主要用户是需要快捷记录的个人，以及需要本地保存／自选存储／自己部署的用户。自部署不能变成普通使用者的学习门槛。

不注册即可完成本地闭环；免费完整导出、恢复和自行部署；官方服务只是免维护的选项；停服、退出账户或订阅到期不阻止本地使用和迁出。客户端、同步服务、数据格式、部署说明都开放，自有代码沿用 MIT，第三方遵循各自许可。

本地数据完整性优先于功能增长，详细保证见[专门规格](本地数据完整性.md)。用户关闭自动备份或从未连接服务器，不能降低正常保存、进程恢复或升级迁移的质量标准。

暂不做社交、排行榜、AI、复杂 RPG、医疗用药管理、健康平台、穿戴设备。普通提醒不承担医疗或闹钟级准点用途。iOS 后续独立制作；Windows／Web 目录不是本轮交付承诺。

## 3. 记录类型与创建

- 完成型：一天完成／未完成，一天最多贡献一个达标日；可撤销与更正。
- 计数型：目标如 8 杯、2000 毫升，快捷加量或输入总量。用十进制定点存储；负数不作为记录，更正原条目处理减少。
- 手动时长：输入分钟，底层整数秒，允许多条累计；首轮没有后台计时器，不能把手填数值当作实测专注时间。

超过目标保留实值，如 10/8；达标贡献仍封顶一天。目标改变未来生效；类型或不可换算单位变更引导新建关联习惯，不把过去“杯”直接当“毫升”。

创建默认名称、完成型、每天、无提醒。图标颜色、分类、目标、开始日期、提醒按需展开。标题 1–80 字符，备注最多 2000 字，导入同样校验。多个每日提醒、自定义凌晨切日、间隔 N 天、结束日期的编辑 UI 后置。

## 4. 频率和状态

| 计划 | 单位 | 达标规则 |
| --- | --- | --- |
| 每天 | 自然日 | 当日完成或达到日目标 |
| 指定星期 | 选中日期 | 当日达到目标；至少选一个星期 |
| 每周 N 天 | 周一至周日 | N=1–7，至少 N 个不同日期达到日目标 |
| 每月 N 天 | 自然月 | N=1–31，至少 N 个不同日期达到日目标 |

周期实际目标为 min(配置 N，周期内有效可执行日期数)。创建前、暂停、休息、归档生效后的日期不在有效日内。整周期无有效日为“休息周期”，不进入分母、不增加或打断连续。暂停导致目标缩减时显示原因。

例：周六创建每周 3 天习惯，首周仅两天有效，目标显示 2；31 天月目标进入有效 28 天的二月则显示 28。已达标周期转入“本周期已达标”，取消余下提醒，但允许额外记录。

| 状态 | 判断 | 统计 |
| --- | --- | --- |
| 待完成 | 今天应执行，尚未达标 | 今天未结算，不进入历史完成率 |
| 部分完成 | 正值但未达日目标 | 日计划结算后计分母、不计达标分子 |
| 已完成 | 达到目标 | 结算后计分子和分母 |
| 未完成 | 应执行日期已结束，未达标 | 日计划计分母；可补记 |
| 休息／暂停 | 明确豁免的日期或区间 | 不计分子分母 |
| 未安排 | 非计划日、开始前或归档后 | 可记录额外行为，不计达标 |

灵活周／月计划按整个周期结算，未达标的一天不逐日算失败。“补记”是记录元信息，不是另一种完成状态。

补记允许修改开始日期至昨天的记录，无付费限制，保留行为日期与实际录入时间；未来日期禁止。开始日前若确有历史，要通过明确历史校正流程调整开始日期并预览影响，不静默接纳异常导入。

休息日有记录时保留为额外行为；取消休息可恢复正常计算。暂停采用 [暂停日期，恢复日期)，恢复默认今天重新可执行。已完成后暂停不删记录。更正事实记录不以“今天是否还可执行”为门禁。

## 5. 编辑、归档和删除

名称、分类、颜色立即更新。日计划目标／频率默认明天生效，灵活计划默认下周／下月生效。已关闭周期不被重算。首轮不提供任意重写历史计划编辑器；历史纠错作为单独受控操作。

归档从明天停用并立即取消未来提醒，今天及此前历史保留；恢复从今天开始，归档间隔不补成失败。删除先进入 30 天回收站，恢复保留全部内容；普通回顾保留删除前贡献。永久删除前显示记录数量、导出入口和确认，删除旧备份中的副本需另行操作。

恢复文件是明确的替换操作，不是普通升级。必须预览影响、自动保护当前数据并确认；不能用一次模糊“恢复”按钮静默覆盖。

## 6. 统计和时间

今日分成“今日应做”和“本周／本月可安排”。今日顶部进度只计算日计划；周期显示如“本周 2/3 天”。不把每周三次伪装成每天必做。

日计划完成率 = 窗口内已结束有效计划日中的达标日数 / 有效计划日数。今天单独显示进度，不纳入历史分母；零分母显示“暂无已结算计划”。

灵活计划显示已结算周期达标率和各周期达标天数／实际目标。选结束日期落在窗口内的完整周期，标注“截至昨天已结算”；进行中周期单列。上周目标 3 天、完成 2 天，周期达标率 0/1、完成量 2/3；本周未结束不能提前算失败。不跨类型合成一个含糊总体百分比。

归档前贡献保留；筛选“仅当前习惯”时明确标注。连续按有效计划日／完整周／月分别计算，休息跳过；今天或当前周期尚未达标但未结算不提前打断，进行中周期达标可计入。单位显示“次计划／周／月”，不统称天数。

新记录保存所属日期、UTC 实际录入时间、当时 IANA 时区和偏移。跟随设备时区影响新记录，不静默重写历史。旅行重复遇到同一天，也不能变成两个达标日。日期计算使用日历运算而非固定 24 小时。

## 7. 数据与服务模式

| 模式 | 能力 | 登录与费用原则 |
| --- | --- | --- |
| 仅本机 | 完整记录回顾、默认数据保护、文件导出恢复 | 无账户、免费、开源 |
| 自选备份 | 系统文件位置；B 增加 WebDAV | 仅存储凭据，无软件解锁费 |
| 自建同步 | 用户的服务器与设备授权 | 完整源码和部署说明开放 |
| 官方托管 | 相同同步功能，免运维 | 可为资源和托管收费，不锁本地、导出或自部署 |

备份成功必须完整写入且校验完成。“已同步”不代表有可回溯备份。服务失效、退出账号和到期不得清除本地数据库或密钥。清除本机是另外明确确认的动作。

## 8. 旧功能取舍

保留分类、主题、备注、日历和合理周期。新用户不默认显示扣分；旧奖励／心愿保存原配置和迁移时余额，在“旧版奖励”只读区查看导出，不能用新规则重新结算。未来奖励采用独立账本和规则版本。

模板只预填，不造历史、不自动开提醒。完整专注计时和 Widget 后置。新用户空白开始，但已有 seed 习惯可能含真实记录，迁移不能仅凭 ID 将其删除。
