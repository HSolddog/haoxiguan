# 大数据量诊断

> 2026-10-02；Linux 云执行器、Flutter test/JIT、后台 isolate 的真实 SQLite 文件、WAL/FULL。以下是瓶颈诊断，不是安卓 release/profile 或真机性能验收。

## 样本和复现

100 个计数习惯、五年日期范围、每习惯 1000 条记录，另有每习惯 20 条备注；逻辑 JSON 28,782,191 字节，数据库约 77.4 MB。数据完全合成，没有备份或同步配置。

```sh
flutter test tools/storage_benchmark.dart \
  --dart-define=BENCHMARK_SAMPLES=5 \
  --dart-define=BENCHMARK_OUTPUT=/tmp/haoxiguan-scale.json
```

脚本只创建新的临时目录，导入后追加记录、关闭连接再重新打开，逐次核对追加总量与习惯数，最后删除自己的临时目录。创建临时数据不触碰应用的真实数据库。

## 结果

| 操作 | 修复前（3 样本） | 修复后（5 样本） |
| --- | --- | --- |
| 保存一条记录 | 28,450 / 29,000 / 28,404 ms | 113 / 81 / 96 / 92 / 76 ms |
| 关闭重开 | 17,526 / 17,164 / 17,040 ms | 7,333 / 6,982 / 7,521 / 6,972 / 6,883 ms |
| 首次导入（1 次） | 59,647 ms | 18,882 ms |

原始数据：[修复前](验收记录/storage-scale-before.json)、[修复后](验收记录/storage-scale-after.json)。重开没有清空 OS 文件缓存，不等同真实冷启动；没有根据 3–5 个样本计算 P95。运行由云资源调度影响。

## 修复与可靠性边界

- 兼容扩展只保存未知字段，不重复深拷贝已解析的整份历史。
- 不可变业务对象作为内存回滚点；事务未提交时仍暴露旧对象。
- 普通修改只校验/提交改变的习惯；完整导入、恢复、同步仍校验完整图。全量导出大小按不可变对象缓存计数，未取消格式上限。
- SQLite 在同一事务检查版本、顺序和新增记录/计划的全局归属；禁止局部校验遗漏未修改习惯的 ID 冲突。批量事实与本地日志同时提交，失败全部回滚。
- 设置变更不扫描记录表。旧仓储仍通过完整快照回退路径工作，冻结 schema 2 APK 的升级夹具继续覆盖兼容性。
- 已增加真实 SQLite 的失败重试、未提交状态不可见、跨习惯 ID 冲突、排序/永久删除、陈旧连接回归；全套 98 项通过。

大库启动和全量导入仍偏慢，继续作为优化与发布门禁。正式目标仍须使用代表性中端 Android 设备、release/profile、至少 30 次样本测冷启动/保存/详情，不能把此处云端 JIT 数值替代目标。
