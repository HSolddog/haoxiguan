# 同步实现与验收

> 2026-10-02。当前为实验性手动同步，可从“数据 → 自有同步服务”进入。正式发布仍受执行计划 C 门禁约束，尤其内容密钥轮换、规模测试、独立密码学评审和 Android 原生联网流程。

## 已实现的使用流程

1. 管理员运行同仓库 Go 服务，配置 HTTPS，并通过 CLI 生成一次性邀请。无 SMTP、第三方账号或专有服务依赖。
2. 首台设备填写服务根地址和邀请，在本地随机生成独立的实体地址密钥和内容密钥。密钥与设备令牌存于 Android Keystore 支持的 secure storage；失败不重置。
3. 首次同步前保存 `.hgr` 加密恢复文件并读回验证。文件仅含空间和内容密钥，不含访问令牌，也不含习惯数据。普通 `.hgb` 是完整业务备份，两者不互相替代。
4. 新设备导入 `.hgr`、输入恢复密码，并使用新的一次性邀请获得自己的设备令牌。服务器无法提供内容密钥或绕过恢复密码。
5. 点击“立即同步”。各设备的主题、排序偏好、安装标识和旧奖励账本保持本地；习惯、记录、计划与每日备注同步。完整文件备份仍保留全部本地数据。
6. 独立新增记录自动合并；同一备注/事实/习惯设置的不同改动进入冲突。以整个习惯为单位选择本机或远端版本，先保护本机快照和同步候选。界面可检查完整候选及最近 20 份保护内容；数据库不自动删除更早保护。
7. 断开仅停用本机同步，不删除本机或远端数据。设备访问撤销单独操作。内容密钥轮换尚未完成，撤销不声称能擦除旧设备已下载的数据。

后台自动备份仍由 WebDAV 提供；当前同步只在用户明确启动时执行，不把备份称为实时同步。同步正在操作时，界面阻止返回；控制器串行排队后续数据操作，完成后重新读取本地 revision，避免旧内存状态覆盖已应用的同步数据。

## 加密协议 v1

- 地址：`base64url_no_padding(HMAC-SHA256(idKey, UTF8("haoxiguan/entity/v1/" + logicalId)))`。
- 逻辑 ID：`h/<habitId>`、`r/<recordId>`、`p/<planId>`、`n/<base64url(JSON([habitId,date]))>`。实体内容认证后才知道其业务 ID；子实体密文含 habitId。
- 内容密钥 32 字节，每次加密新随机 24 字节 nonce；XChaCha20-Poly1305，16 字节认证标签。
- 明文为 UTF-8 JSON `{logicalId,payload}`，单对象最多 128 KiB。删除仍有经过认证的 `payload:null` 密文，不使用未认证的空负载。
- 精确 AAD 为紧凑 JSON 数组的 UTF-8：`["haoxiguan-sync-object",1,vaultId,encryptionEpoch,entityId,baseRevision,deleted,keyGeneration]`。
- 不透明 ciphertext 是以下 JSON 的 UTF-8 字节再作标准 Base64：`{v:1,generation,nonce:<Base64>,ciphertext:<Base64>}`。
- 服务端 revision 必须为 baseRevision+1；服务器恢复 epoch 与对象原加密 epoch 分离。更换头字段、地址、删除状态或密钥会认证失败。
- 独立 Python + 系统 libsodium 向量在 `tools/sync_test_vector.py` 和 `test/fixtures/sync-v1-vector.json`。Dart 测试验证相同密文、地址、AAD、篡改及缺失密钥。
- `.hgr` 使用不同 magic `haoxiguan-sync-recovery`，版本 1，Argon2id 64 MiB / 3 次 / 并行度 1、16 字节 salt、同一 AEAD。头字段固定并全部绑定 AAD；文件最多 128 KiB，派生前拒绝任何其他 KDF 参数。密码至少 12 字符，最多 UTF-8 1024 字节。
- `.hgr` AAD：`[format,version,suite,memoryKiB,iterations,parallelism,salt,nonce]`。恢复后的 keyring 格式和代际严格校验。

服务器仍可看到账户、设备、连接时间、随机对象地址、版本、删除标记和密文大小。SQLite 本地数据依赖系统沙箱/磁盘保护；没有把它宣传为应用层数据库加密。内存 key buffer 尽力清零，Dart 不可变字符串无法保证擦除。

## 事务和故障语义

SQLite schema 3 增加 `sync_state` 和 `sync_protections`，不重建业务表。schema 1 先执行原领域迁移，schema 2 仅增加同步表；版本号与内容在同一事务提交。未来 schema 拒绝打开而不清空。

`sync_state` 保存绑定、游标、高水位、远端 shadow、已应用基线、固定 outbox 和冲突；不含密钥、邀请或令牌。一次业务快照和同步状态从同一 SQLite 读事务取得。落盘时同时检查业务 revision 和同步 revision；任何并发本地提交使陈旧帧失败，不覆盖新事实。

待发送操作的 opId、baseRevision、nonce 和密文先持久化，再发 HTTP。回应丢失会逐字节重试同操作；服务器在同事务保存 CAS 结果和幂等回执。多批初次上传先完成全部固定 outbox，再合并远端图，避免本机被中间状态误判。其他设备若读到未见过的半个习惯会等待重试，不安装不完整图。

pull 分页先解密和验证对象，再将 shadow 与 cursor 一起落盘；完整高水位之后才合并业务图。接收期间崩溃可重复取页，不跨过未落盘内容。布尔同日完成使用稳定记录 ID，同一完成事实自动归并；数值新增不同 ID 合并。同一实体冲突、父删除与子修改、同日重叠计划都不静默取最新时间。

本地恢复完整备份会改变本地 vaultId，因此旧同步配置停止。服务器从旧备份恢复必须停服执行 `rotate-epoch`：同时废止所有旧会话、邀请和设备授权。用户重新获得邀请后明确选择“重新核对基线”；所有不同习惯逐一核对，旧服务缺失不能自动删除本地已确认记录。

## 当前实测

本地 Flutter 静态分析通过，90 项自动化通过；真实 WebDAV/Go 集成默认跳过，分别显式运行。新增同步覆盖：两设备离线计数、回应丢失与关闭重开、并发备注、pull 提交失败、同步期间前台写入、布尔幂等、多批初始上传、删除与离线备注、基线恢复和错误密钥。

真实 Go 1.27.1 + SQLite 服务经本地 HTTPS 代理联调通过：两份一次性邀请、客户端内容加密、恢复文件换机、离线合并、冲突处理、设备撤销 401、删除远端账户后本地数据不变。测试使用隔离合成账户和显式信任的测试证书，没有关闭 TLS 校验，没有生产用户数据。测试源为 `test/sync_integration_test.dart`。

原生 API 24/35/36 的无云本地写入、Keystore、文件加密、强制停止、重开、同签名版本覆盖已通过，见[验收记录](验收记录/2026-10-02.md)。该批 schema 2 → 2；新加入的冻结 schema 2 → 当前 schema 3 用例将在下次 CI 运行，尚未记为通过。

## 尚未通过的 C 门禁

- 内容密钥轮换/新设备安全获得当前代际；当前 keyring 有代际编码，但尚无服务端原子重加密切换。
- 同步 state 当前为 SQLite 中的 JSON 文档，业务仓储也按快照组装。十万对象的内存、延迟和历史配额尚未测量，不能宣称已经达到设计性能。
- 原生安卓同步界面的端到端联网、授权恢复和文件选择；当前跨设备客户端测试运行于 Flutter 主机测试环境。
- ARM64 服务真实运行、生产 HTTPS/升级/异机恢复演练、独立密码学评审、公开服务运维条款。

这些限制不影响已经实现的无账号单机记录和独立加密文件/WebDAV 备份。后续完成对应证据后再移除实验标识。
